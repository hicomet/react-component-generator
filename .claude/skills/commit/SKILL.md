# Commit

변경사항을 읽고, 의미 단위로 나누고, 컨벤션에 맞는 한국어 메시지를 만든 다음 **승인을 기다리지 않고 바로** 커밋한다.
사용자가 커밋을 요청한 것 자체가 승인이므로 중간에 되묻지 않는다. 대신 결과를 투명하게 보고한다.

## 절차

### 1. 변경사항 분석
- `git status --short`로 전체 변경 파일(untracked 포함)을 파악한다.
- `git diff`(unstaged)와 `git diff --staged`(staged)를 모두 읽는다. 이미 staged된 것이 있으면 사용자가 의도해서 올린 것일 수 있으므로 존중한다.
- `git log --oneline -10`으로 이 저장소의 기존 메시지 스타일을 확인해 톤을 맞춘다.
- 변경이 없으면 "커밋할 변경사항이 없습니다"라고 알리고 끝낸다.
- git 저장소가 아니면 그 사실만 알리고 중단한다(임의로 `git init` 하지 않는다).

### 2. 논리적 단위로 분류
- 하나의 커밋은 **하나의 목적**만 담는다. 기능 추가, 버그 수정, 리팩터링, 설정 변경이 섞여 있으면 나눈다.
- 같은 목적에 속한 파일(예: 컴포넌트 + 그 테스트 + 타입)은 한 커밋으로 묶는다.
- 한 파일 안에 서로 다른 목적의 변경이 섞여 있으면 `git add -p`로 hunk 단위 분리를 제안한다. 어렵거나 위험하면 한 커밋으로 묶되 이유를 알린다.
- 의존 순서가 있으면(예: 타입 정의 → 사용처) 빌드가 깨지지 않는 순서로 배치한다.

### 3. 커밋 메시지 작성
형식:

```
<type>: <한국어 요약>

<필요할 때만: 왜 바꿨는지, 주의할 점>
```

| type | 용도 |
|------|------|
| feat | 사용자에게 보이는 기능 추가 |
| fix | 버그 수정 |
| refactor | 동작 변화 없는 구조 개선 |
| chore | 빌드·설정·의존성·문서 등 코드 동작과 무관한 잡무 |

- 요약은 **무엇이 달라졌는지**를 한 줄(대략 50자 이내)로, 마침표 없이 쓴다. 파일 나열이 아니라 의도를 적는다.
- 본문은 요약만으로 "왜"가 전달되지 않을 때만 쓴다. diff에서 보이는 내용을 반복하지 않는다.
- 위 4개로 애매한 경우(문서만, 테스트만, 스타일 등)는 가장 가까운 type을 고르고, 저장소 로그에 이미 `docs:`·`test:` 같은 관례가 있으면 그걸 따른다.
- 예:
  - `feat: 컴포넌트 생성기에 props 타입 자동 추론 추가`
  - `fix: 빈 입력일 때 미리보기가 깨지는 문제 수정`
  - `refactor: 템플릿 렌더링 로직을 별도 모듈로 분리`
  - `chore: eslint 설정 갱신 및 미사용 의존성 제거`

### 4. 커밋 실행
- 분류한 커밋마다 **파일을 개별 지정**해 `git add <파일들>` 후 `git commit`한다. `git add -A`/`git add .`는 의도치 않은 파일을 끌어들이므로 쓰지 않는다.
- 메시지는 HEREDOC으로 넘겨 줄바꿈과 한글이 깨지지 않게 한다.
- 시스템 컨텍스트에 커밋 attribution 지침(Co-Authored-By 등)이 있으면 메시지 끝에 붙인다.
- hook이 실패하면 원인을 보고하고 고친 뒤 **새 커밋**으로 만든다. `--no-verify`, `--amend`, force push는 사용자가 요청하지 않는 한 쓰지 않는다.
- push는 요청받지 않았으면 하지 않는다.
- 끝나면 `git log --oneline -N`으로 만든 커밋 목록(type, 요약, 포함 파일)을 보고한다. 잘못 나뉘었거나 메시지를 고치고 싶으면 사용자가 사후에 요청한다.

## 커밋에서 제외할 것
승인 단계가 없으므로 아래 항목은 사전에 묻지 않고 **커밋하지 않은 채 남겨 두고**, 마지막 보고에서 알린다.
- `.env`, 키·토큰·비밀번호가 담긴 파일, 인증서 개인키 등 **크리덴셜 의심 파일**은 스테이징하지 않는다. 값 자체는 출력하지 않고 파일명만 언급한다.
- 빌드 산출물, `node_modules`, 로그, 임시 파일 중 `.gitignore` 대상이 아닌 것도 제외하고 보고한다.
- 변경 diff 안에 디버그 코드(`console.log`, `debugger`)가 보이면 커밋은 진행하되 보고에서 알린다.
